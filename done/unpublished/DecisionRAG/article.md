# DecisionRAG：不靠檢索器，讓決策模型沿著語料樹找資料

**來源**：[DecisionRAG（arXiv 2610.35868v1）](https://arxiv.org/abs/2610.35868v1)（Cornell、ASAPP，2026/10）

## 前言

RAG 系統裡，生成模型越換越強，負責決定「它能看到什麼」的檢索器卻還是 BM25 或向量檢索。DecisionRAG 的做法是乾脆不讓檢索器先篩：把語料整理成一棵樹，從上往下每一層都由一個決策模型（Jev 1.13）判斷哪些分支值得往下翻，全程不生成任何 token。

這裡的「決策模型」，指的是不逐字寫出答案、而是直接對每個選項給出機率的模型：問它「這頁值不值得翻？」，它回的是 yes 的機率，而不是一段文字。論文用的 Jev 1.13 是供應商的線上服務，只能透過 API 使用，模型大小未公開。

結果是準確度和最強的「向量檢索 + GPT-5 重排」大約打平，延遲快一個數量級。但這篇也有不少要打折看的地方，例如四個資料集的最佳成績其實都出自「混入向量檢索候選」的混合版，論文標榜的「retriever-free」（無檢索器）名不符實。

本文先講問題和方法，再看實驗數字，接著用五個追問把容易誤會的細節講清楚，最後整理兩個脫離這篇論文也用得上的概念。文中標（推論）的是筆記作者的推測、標（自編）的是為了說明而自己編的數字、標（一般知識）的是論文以外的背景，其餘都是論文內容；論文沒交代清楚的地方會直接寫「論文未說明」。

## 問題：檢索器跟不上生成模型

在 RAG 裡，決定生成模型能看到什麼的是檢索器，而檢索器遠比生成模型笨。檢索器漏掉的證據，生成模型再強也救不回來。論文把這叫做**能力不對稱**（capability asymmetry）。

![左邊是簡單檢索器卡住強大 LLM 的示意，右邊是改用決策模型做檢索後兩邊能力拉平。](img-001)
*圖 1 — 能力不對稱：簡單的檢索器成為強大 LLM 的瓶頸（a），改用決策模型做檢索讓兩邊能力拉平（b）。（來源：原始論文 Figure 1。）*

舉個具體的查詢：「Christopher Nolan 2000 年那部電影的主角是誰？」要答這題，得先推出「Nolan 的 2000 年作品是 Memento」，才知道該去 Memento 頁面找介紹主角 Leonard Shelby 的段落。麻煩的是「Memento」這個詞根本不在查詢裡。

- **BM25** 只比字面，會把標題剛好含「2000」和「film」的 Gladiator (2000 film) 排在 Memento 前面。
- **Dense retrieval**（向量檢索）把查詢和段落分開編碼，同樣沒有機會在讀過查詢之後推理這一步。

![三欄示意圖：(a) BM25、(b) 向量檢索靠比對字詞或向量，(c) DecisionRAG 沿著文件結構一層層做決策。](img-002)
*圖 2 — 靠比對檢索與靠決策檢索的對照。圖中 (a) 的 BM25 分數只是示意。（來源：原始論文 Figure 2。）*

### 現有補救做法都卡在某一處

| 做法 | 強模型參與判斷？ | 能找回第一階段漏掉的？ | 速度 |
| --- | --- | --- | --- |
| BM25／dense retrieval | 否 | 不適用 | 快 |
| 重排序（reranker） | 是，但只看第一階段的候選 | 否 | 中 |
| 生成式導航（LLM 逐步搜尋，或沿文件階層逐字寫出要保留的分支） | 是 | 是 | 慢 |
| DecisionRAG 想達成的 | 是 | 是 | 快 |

從這張表可以整理出三個挑戰：

- **不依賴第一階段檢索器**：強模型要直接決定「看什麼」，而不只是重排別人挑好的。
- **不能逐字生成**：每一步判斷都要快。
- **規模**：語料可達數百萬段，不可能讓模型逐段讀過。

## DecisionRAG 怎麼運作

30 秒版本：離線先把語料整理成一棵樹；上線時，決策模型（下文稱「審查員」）在每一層對所有候選出是非題、只留前幾名，到段落層留前 $r$ 段，最後對前 $m$ 段出一題決選題。比喻成在圖書館找資料，就是先看分區，再挑書，最後翻到段落。

### 系統全貌

整套系統分成三塊：

- **離線（只建一次）**：把語料整理成「分群 → 頁面 → 段落」這類階層樹，每個節點配一段短描述（做法見〈語料樹從哪來〉）。
- **上線（每個查詢都走一遍）**：審查員在三個地方出題。前兩個是是非題（上層節點篩選、段落篩選），最後一個是決選題（排第一名）。
- **兩個可選的補救後門**：dense 候選和 notepad，都把段落送回段落層（見〈補救剪錯的兩個後門〉）。

### 是非題：讀一次 context，同時回答 n 題

每個候選各自一題 yes／no，所有題目共用同一個 context，一次 forward pass 答完（論文 Equation 2）：

$$
p_i^{\text{bin}} = P(\text{Yes} \mid s,\ Q_i)
$$

其中 $s$ 是共享 context，也就是使用者問題加上所有候選的描述；$Q_i$ 是第 $i$ 題，例如「回答問題所需的資訊在頁面 $i$ 裡嗎？」；$p_i^{\text{bin}}$ 是第 $i$ 個候選的分數，拿來排序和剪枝。

![兩個面板：上面是對文件 D1 到 D3 平行出是非題，機率加總 1.84；下面是對前幾段出多選一，機率加總為 1。](img-003)
*圖 3 — 決策模型的兩種判斷方式，都在同一個只讀一次的共享 context 上進行：(a) 平行是非題，(b) 多選一重排。（來源：原始論文 Figure 3。）*

每題的機率只在自己的 yes 和 no 之間分配，所以跨題加總不必是 1。圖 3(a) 的示意值是 Memento (film) 0.96、Christopher Nolan 0.81、Gladiator (2000 film) 0.07，加起來 1.84。因為每題獨立，候選數只受 context 長度限制；一層太大時就拆成多個平行請求，最後合併分數排序。三個判斷階段的完整輸入輸出範例，見〈Q1 每個判斷階段，模型的輸入和輸出到底長什麼樣？〉。

### 同一張桌子：分數為什麼能互相比較

題目之間彼此看不到，但所有候選都寫在同一個 context 裡，就像所有應徵者圍著同一張桌子一起面試，所以每一題都是在「看過全部對手」的條件下作答。有更好的候選在場時，原本看起來還不錯的候選分數就會被壓低。

|  | 分開判斷：每個請求只放一段 | 一起判斷：同一個 context |
| --- | --- | --- |
| A：主角是 Leonard Shelby（真答案） | 0.85 | 0.93 |
| B：Nolan 的電影生涯（相關但沒有答案） | 0.88 | 0.30 |
| 排第一 | B（錯） | A（對） |

（自編）上表數字僅為示意。分開判斷時，兩個分數不是同一把尺量出來的，放在一起排序就會出錯。

這不是數學保證：分數仍然是各自的二選一，「壓低對手」的效果要靠模型自己學會。論文 6.2 節把這個效果叫 calibration（校準），但用法比統計上的原意寬鬆，實際指的是「分數彼此可比」。

### 決選題：最後一步只排第一名

到了最後，對前 $m$ 段出唯一一題「哪一段最相關？」，所有候選搶同一份機率（論文 Equation 3）：

$$
p_i^{\text{mul}} = P(a_i \mid s,\ Q,\ \mathcal{A}), \qquad \sum_{i=1}^{m} p_i^{\text{mul}} = 1
$$

這裡的 $s$ 是新組的 context，只放問題和前 $m$ 段；$Q$ 是那一題；$\mathcal{A} = \{a_1, \dots, a_m\}$ 是 $m$ 個段落選項。圖 3(b) 的示意值是主角段落 0.91、「讓 Nolan 一舉成名」那段 0.09。

|  | 是非題 | 決選題 |
| --- | --- | --- |
| 用在哪 | 每一層篩選 | 只在最後一步 |
| 目標 | 召回：不要漏 | 第一名排對 |
| 候選上限 | 只受 context 長度限制 | 最多 255 個選項（Jev 的限制） |
| 機率怎麼分 | 每題各自在 yes／no 之間分 | 所有候選搶同一份 1 |

實際設定是 $m = 20$（Natural Questions 為 5）。前 $m$ 名照決選機率重排，其餘維持是非題的排序。MTRAG 比較特別，只把決選第一名提到最前面，原因論文未說明。

### 剪枝與預算

被剪掉的分支，這個查詢就不會再看了。所以每層的預算刻意放寬，用成本換召回。名額可以是固定的前 $k$ 個，也可以是機率門檻。

### 補救剪錯的兩個後門

**dense 候選**：另外用向量檢索撈前 20 段（ConditionalQA 為 10 段），去重後依頁面與章節、按閱讀順序併入段落層。這裡的眉角是：用了它就需要事先建好向量索引，系統不再是「無檢索器」，比較準確的說法是「導航為主、向量檢索補漏」的混合版。

**notepad**（只用在多輪對話資料集）：記錄最近幾個對話輪中排第一的段落所在頁面；在 MultiDoc2Dial 上，最近 2 個 notepad 頁面的段落會繞過頁面層、直接進段落層。怎麼排序、進來後會不會被選上，以及 MTRAG 的情況，見〈Q3 notepad 是直接放進段落層嗎？〉。

### 語料樹從哪來

每個節點都要有一段短描述給審查員判斷：段落用內文，頁面用標題（有些資料集再加章節標題），群用一句摘要。

有現成結構就沿用，例如 metadata 欄位、HTML 的 h1／h2、網址路徑。樹不必處處一樣深，MTRAG 只替超過 60 段的長頁多插一層章節。沒有結構時（例如 Wikipedia）就先分群再寫描述，做法和背後的道理見〈樹狀導航的上限由節點描述決定〉。

另外要分清楚：查詢時不需要向量檢索，但建樹時可能會用 embedding 來分群。

### 自訓審查員：一次 forward pass 怎麼同時答多題

除了 Jev，論文也自訓了開源審查員（Appendix G），以 Qwen3-Base 為底，把輸出頭換成評分頭。

輸入的排法是：每個候選一題，題目後面接「no」「yes」兩個選項，全部接在共享 context 之後。關鍵在於**每一題的位置編號都從 context 結束處起算，題目之間用 attention 遮罩互相隔開**；機制、可能的設計動機和它沒解決的偏差，見〈Q4 位置編號是不是都當作接在 context 後面？〉。

評分頭的算法：取題目結尾 token 的向量 $q$，以及兩個選項結尾 token 的向量 $v_{\text{yes}}$、$v_{\text{no}}$，算餘弦相似度再乘上學到的溫度 $\tau$（上限 100），最後做 softmax：

$$
P(\text{yes}) = \frac{\exp(\tau \cos(q, v_{\text{yes}}))}{\exp(\tau \cos(q, v_{\text{yes}})) + \exp(\tau \cos(q, v_{\text{no}}))}
$$

（自編）舉例：$\cos(q, v_{\text{yes}}) = 0.30$、$\cos(q, v_{\text{no}}) = 0.10$、$\tau = 20$，則 $P(\text{yes}) = 1 / (1 + e^{-4}) \approx 0.982$。Jev 本身是不是也這樣做，論文未說明。

## 實驗：準確度與延遲

先講結論：準確度和最強的「向量檢索 + GPT-5 重排」大約打平，混合版小勝；延遲快一個數量級，但成本只在小語料上佔優。

### 讀表需要的最少知識

| 資料集 | 內容 | 規模 | 每題正確段落數 |
| --- | --- | --- | --- |
| MultiDoc2Dial（MD2D） | 美國政府說明中心的多輪客服對話 | 413 頁、4,110 段；4,201 輪 | 1 |
| ConditionalQA（CQA） | 英國政府指南的情境題 | 652 頁、5.8 萬段；271 題 | 1–22 |
| MTRAG | IBM Cloud 技術文件的多輪對話 | 8,578 頁、7.2 萬段；188 輪 | 1–7 |
| Natural Questions（NQ） | 真實搜尋問題，答案在 Wikipedia | 10.9 萬頁、268 萬段；500 題 | 1–3 |

兩個指標：

- **R@k（Recall@k）**：正確段落中有幾成出現在前 $k$ 名，衡量「有沒有找回來」。MD2D 每題只有 1 個正確段落，所以它的 R@1 就等於「第一名對不對」。
- **Hit@1**：第一名剛好是正確段落之一的題目比例，衡量「第一名排對沒有」，用在正確段落不只一個的資料集。

各資料集的主指標：MD2D 看 R@1、CQA 看 Hit@1、MTRAG 看 R@5、NQ 看 Hit@1。

> MTRAG 的正確答案有一部分是 GPT-5 補標的，而 GPT-5 同時也是被比較的 baseline，這個資料集的數字要打折看（論文 Appendix A.3）。

### 提升來自導航，還是來自 Jev？

論文 6.5 節讓 Jev 直接重排向量檢索的前 100 段，打分方式和 DecisionRAG 最後一步完全相同，兩邊只差在「候選從哪來」。CQA 和 NQ 可以和表 1 用同一批題目串起來：

| Hit@1（%） | Dense 前 100 + Qwen3-Reranker | Dense 前 100 + Jev 重排 | DecisionRAG + dense 候選 |
| --- | --- | --- | --- |
| CQA（271 題） | 64.6 | 65.7（+1.1） | 73.4（+7.7，95% CI [2.6, 13.3]） |
| NQ（500 題） | 48.0 | 59.4（+11.4） | 66.4（+7.0，95% CI [3.4, 10.8]） |
*表 2 — 同一個向量索引下，專用 reranker、Jev 重排與沿樹導航的比較。括號內是相對左邊一欄的差距。（來源：原始論文 Table 2、Table 8。）*

另外兩個資料集上，導航和 Jev 重排持平：

- **MD2D**（1,000 輪抽樣）：兩者的 R@1 是 49.9 和 51.2。
- **MTRAG**（只用官方原始標註）：兩者的 R@5 是 38.3 和 38.7。

兩邊都差不到 1.5 點（哪個數字屬於哪個方法，本文的資料來源沒有標明）。評估範圍和表 1 不同，所以不能和表 1 的數字直接比。也就是說，四個資料集裡有兩個，導航本身沒有額外貢獻。

> **觀察一：Jev 重排勝過 Qwen3-Reranker。** 這打破的不是「檢索之後要重排」，而是「重排就該用專門訓練的 reranker」。兩者其實有兩個差別，論文沒有拆開：一是模型本身（通用決策模型 vs 專用 8B reranker），二是打分方式（100 段放進同一個 context 一起判斷再加決選題 vs 每對問題與段落各自打分）。幅度也看資料：NQ 差 11.4 點，CQA 只差 1.1 點。

> **觀察二：導航勝在排得準，不是找得全。** 向量檢索的前 100 名其實更常包含正確段落（NQ 98.4% 對 94.0%；CQA 98.5% 對 91.1%）。但只看兩邊都包含正確段落的題目，導航把它排第一的比例更高（NQ 70.1% 對 61.9%；CQA 76.7% 對 67.3%）。作者推測，原因是導航把整頁段落按閱讀順序交給審查員，向量檢索給的卻是來自不同頁面的零散段落；這個解釋沒有經過實驗驗證。

### 延遲與成本

延遲是每查詢的中位數秒數，成本是每查詢的 API 費用（美分）。DecisionRAG 的計時只用了 48、50、24、100 個查詢（論文 Table 15）。

|  | MD2D | CQA | MTRAG | NQ |
| --- | --- | --- | --- | --- |
| 延遲：Dense + Qwen3-Reranker | 7.5 | 3.3 | 14.3 | 5.8 |
| 延遲：Dense + GPT-5 重排 | 11.8 | 14.4 | 12.2 | 15.0 |
| 延遲：DecisionRAG | 0.68 | 0.82 | 1.76 | 1.73 |
| 成本：Dense + GPT-5 重排 | 1.40 | 1.20 | 1.90 | 1.40 |
| 成本：DecisionRAG | 0.22 | 0.29 | 1.73 | 2.33 |
*表 3 — 每查詢的中位數延遲（秒）與 API 成本（美分）。（來源：原始論文 Table 5。）*

這些倍數不能當成公平控制下的加速比，論文 Appendix F 自己也承認，因為兩邊的部署條件差很多：

|  | Qwen3-Reranker 那一列 | DecisionRAG 那一列 |
| --- | --- | --- |
| 模型 | 8B 專用 reranker | Jev 1.13，大小未公開 |
| 硬體 | 單張 RTX A6000，本機執行 | 供應商線上服務，硬體不明 |
| 平行度 | 100 段分批送進同一張 GPU | 每查詢最多同時 8 個請求 |

比較保守的結論是：在論文的測試條件下，「Jev API + 沿樹導航」端到端比「本機單卡 8B reranker」和「GPT-5 重排」快一個數量級；至於決策模型這一類模型本身是不是比 reranker 快，這篇沒有證據。

從結構上看（推論），把所有候選寫進同一個 context 的做法，等於把所有段落串成一條長序列，attention 的計算量隨長度平方成長，不一定比 cross-encoder 逐對打分省。

成本方面，大語料反而比較貴：NQ 每查詢 2.33 美分，高於 GPT-5 重排的 1.40，因為頁面層要判斷約 17,500 個標題。另外 Jev 1.13 只能透過 API 使用，換成自訓模型之後的延遲和成本，論文沒有測。

### 同一棵樹：用判斷 vs 用生成

論文 6.3 節保持樹和預算不變，只把審查員換成 GPT-5（低推理強度），讓它讀完一層之後逐字寫出要保留的編號。兩邊都走 API，是全篇最乾淨的延遲比較（CQA 271 題；NQ 只用前 100 題，也沒有信賴區間）。

|  | Hit@1 | R@10 | 延遲（秒） | 成本（美分） |
| --- | --- | --- | --- | --- |
| CQA：GPT-5 生成式 | 73.8 | 73.6 | 28.2 | 6.1 |
| CQA：DecisionRAG | 69.7 | 71.9 | 0.82 | 0.29 |
| CQA：DecisionRAG + dense | 73.4 | 76.3 | 0.85 | 0.29 |
| NQ：GPT-5 生成式 | 59.0 | 82.5 | 250.8 | 57.2 |
| NQ：DecisionRAG | 65.0 | 86.5 | 1.73 | 2.33 |

表 4 裡準確度互有勝負（CQA 上 GPT-5 多 4.1，NQ 上 DecisionRAG 多 6.0），但延遲差 34 到 145 倍，成本差 21 到 25 倍。NQ 上 GPT-5 每查詢要超過 4 分鐘：它得先讀完整層，再一個個寫出編號，分群層要選 150 個時還常常需要追問補齊。這是全篇最直接支持「決策模型適合做檢索決策」的證據。

## 追問：五個容易誤會的細節

以下五個問題各自獨立，不需要按順序讀。

### Q1 每個判斷階段，模型的輸入和輸出到底長什麼樣？

下面把一次查詢拆成三個判斷階段。每個階段都重新組一個 context：「使用者問題 + 編號的候選描述（依所屬頁面分組、按閱讀順序）」，後面接題目。上一階段的分數不會帶進下一階段的輸入（論文 Appendix B.1）。以「Christopher Nolan 2000 年那部電影的主角是誰？」為例：

**階段 ①：頁面層是非題**

- context：問題；頁面 1 Memento (film)；頁面 2 Christopher Nolan；頁面 3 Gladiator (2000 film)；…其餘候選標題。
- 題目：每頁一題「回答問題所需的資訊在頁面 n 裡嗎？」（yes／no），同一次 forward pass 答完。
- 輸出：每頁一個 $P(\text{yes})$，例如 0.96、0.81、0.07，加總 1.84（圖 3(a)）。
- 用途：留前 $k$ 頁，展開它們的全部段落。

**階段 ②：段落層是非題**

- context：問題；頁面 Memento (film) 底下的段落 1「主角是 Leonard Shelby…」、段落 2「讓 Nolan 一舉成名…」；頁面 Christopher Nolan 底下的段落 3「Nolan 的婚姻…」。
- 題目：每段一題「第 n 段含有回答問題所需的資訊嗎？」
- 輸出：每段一個 $P(\text{yes})$，彼此獨立，加總不必為 1。
- 用途：排序後留前 $r$ 段，前 $m$ 段進階段 ③。

**階段 ③：決選題**

- context：新組的，只放問題和前 $m$ 段。
- 題目：一題「哪一段最相關？」，選項就是這 $m$ 段（實際問句論文未給，圖 3(b) 只是示意）。
- 輸出：一個機率分布，例如 0.91、0.09，加總為 1。
- 用途：前 $m$ 名照這個分布重排，第 $m+1$ 到 $r$ 名維持階段 ② 的順序。

頁面的描述依資料集而定：MD2D 與 MTRAG 用標題加章節標題，CQA 用標題加最上層章節標題，NQ 只用標題。NQ 在階段 ① 之前還多一層「主題分群」，做法相同；MD2D 則在頁面層之上多一層「說明中心」（見〈Q3 notepad 是直接放進段落層嗎？〉）。

### Q2 同一個 context 放越多候選，判斷品質會變差嗎？

在這個設計裡，「題目變多」和「context 變長」永遠一起發生，所以真正要問的是：一個請求放越多候選，排序會不會變差？在論文測過的範圍內不會，從 1 個加到大約 50 個反而變好，之後持平。

**固定難度，只改請求大小**（論文 6.2 節，NQ 289 題）：每題固定 200 個候選，拆成每個請求 $m$ 個，再合併排序。Hit@1 從每請求 1 個的 47.8% 升到 50 個的 54.3%，到 100、200 個都持平（圖 4）。

![折線圖：固定 200 個候選，橫軸是每個請求放幾個候選（1 到 200），縱軸是 Hit@1；到 50 個以上就不再因為拆分而掉分。](img-012)
*圖 4 — 固定 200 個候選、拆成每個請求 $m$ 個時，Natural Questions 的 Hit@1（289 題，色帶為 95% 區間）。（來源：原始論文 Figure 6。）*

**非常長的 context**（論文 Appendix F，MTRAG 188 輪）：篩 8,578 個頁面標題時，比較「每請求最多 150k tokens」和「最多 10k tokens」兩種拆法，R@5 與 nDCG@5（會考慮名次的排序品質指標）只差 −0.7 和 −0.2 點，信賴區間都包含 0。

**容易誤讀的是圖 5**：候選池從 5 長到 1,000 時，Hit@1 一路下降（1,000 個時 47.6%）。但池子變大時會混進更多 hard negative（看起來很像答案、其實不是的段落），題目本身變難了，不能拿來當「context 變長會傷品質」的證據。這張圖該看的是：同樣的池子大小下，一起判斷一直勝過分開判斷。

![折線圖：橫軸是候選池大小 N（5 到 1,000），縱軸是 Hit@1，比較每段一個請求、全部放一個請求的是非題，以及多選一排序。](img-010)
*圖 5 — 候選池變大、所有候選在同一個請求裡一起打分時，Natural Questions 的 Hit@1（150 題）。（來源：原始論文 Figure 5。）*

> **沒被回答的部分**：每題 yes／no 的絕對正確率論文沒測，只測了排序。$P(\text{yes})$ 的絕對值可能會隨 context 長度漂移，卻不影響排序（推論），所以如果要拿 $P(\text{yes})$ 去對門檻值，這件事沒有被驗證過。另外，排序只測到 200 個候選，長 context 也只測了「篩頁面標題」這一種任務。

### Q3 notepad 是直接放進段落層嗎？

在 MultiDoc2Dial 上，是。notepad 在三個層級各自是這樣進來的：

| 層級 | notepad 怎麼進來 | 原文講清楚了嗎 |
| --- | --- | --- |
| 說明中心層 | 最近取過的頁面所屬的中心一定保留 | 清楚（B.2） |
| 頁面層 | context 列出 notepad 頁面 | 不清楚，見下 |
| 段落層 | 最近 2 個 notepad 頁面的所有段落直接加入是非題，不經頁面層篩選 | 清楚（4.2、B.2） |

原文對頁面層只有一句「The page-stage context lists the notepad pages.」，可以有兩種讀法：

- **讀法 A**：當作提示資訊，那些頁面仍要靠自己的是非題爭名額，可能被剪掉。
- **讀法 B**：當作額外的候選。

（推論）讀法 A 比較合理，因為說明中心層已經保證那一頁所屬的中心會被保留、那一頁會出現在候選裡；但光看原文沒辦法區分。

三個常見誤解：

- notepad 記的是「最近」不是「名次」：每個對話輪結束後，只有那一輪排第一的段落所屬頁面會移到最前面；連續兩個對話輪落在同一頁，只佔一個位置。
- 段落加入的是段落層的是非題，之後還得擠進前 $m$ 名才進得了決選題。後門保證「能被看到」，不保證「會被選上」。
- MTRAG 也用 notepad，但它是否也把段落直接加進段落層，論文沒說。

### Q4 位置編號是不是都當作接在 context 後面？

是，但光靠位置編號不夠，要和 attention 遮罩一起用。原文的描述是：所有題目都從 context 結束後的位置開始，而且彼此不能互相 attend（論文 Appendix G）。用（自編）的長度舉例：

|  | 在序列中實際的格子 | 給模型的位置編號 |
| --- | --- | --- |
| context | 0–999 | 0–999 |
| 題目 1 | 1000–1019 | 1000–1019 |
| 題目 2 | 1020–1044（排在題目 1 後面） | 1000–1024（與題目 1 重疊） |

- **位置編號重疊**：每一題感受到的「自己和 context 的距離」，都和「只有這一題」時一樣。（一般知識）Qwen3 用 RoPE，attention 看的是相對距離。
- **attention 遮罩**：題目 2 看不到題目 1。少了它，題目 2 會讀到題目 1 的內容，就不再是獨立判斷。

兩者合起來的效果，以及這招怎麼套用到別的場景，見〈多題共用一個 context 的實作技巧〉。

**為什麼要這樣設計？**（推論，論文未說明動機）如果位置照實際順序往後排，越後面的題目離 context 越遠，模型可能偏好或壓低後面的候選。全部從同一個位置起算，題目在位置上就對稱了，「題目排第幾」的偏差就此消除。

**但候選內容在 context 裡仍有先後順序。** 候選 1 的描述在開頭、候選 200 在結尾，兩者和題目的距離不同，這部分的偏差沒有被消除，論文也沒測過打亂候選順序會怎樣。另外，選項「no」「yes」的位置編號怎麼排，論文也沒交代。

### Q5 主結果表為什麼看不到 BM25？

其實看得到：論文 Table 2 有 BM25、SPLADE++ 和單純 Dense，本文表 1 也全部收錄了。BM25 那一列正好量化了能力不對稱：NQ 上 BM25 的 Hit@1 只有 16.4，DecisionRAG 是 65.4。

不過 BM25 不是 DecisionRAG 真正的對手，拿它來比只會放大提升幅度。要判斷這個方法值不值得用，該對照的是最強的「Dense + GPT-5 重排」。

## 值得帶走的兩個概念

這兩點脫離 DecisionRAG 也成立。

### 多題共用一個 context 的實作技巧

**適用情境**：一段很長的共同前綴，後面接 N 個彼此獨立的判斷。例如同一個問題配 N 個候選段落、同一段文字的 N 個分類題、同一個 prompt 配 N 個回覆交給 reward model 打分。

**做法：下面三步要一起做，位置編號和遮罩缺一不可。**

1. 把前綴和 N 個分支串成一條序列。
2. 每個分支的位置編號，都從前綴結束處重新起算。
3. 加 attention 遮罩：每個分支只看得到前綴和自己，看不到其他分支。

算出來的結果等同於把「前綴 + 第 $i$ 個分支」分開跑 N 次，但前綴只算一次。

**好處**：前綴的計算共用；每個分支與前綴的相對距離相同，不會因為排第幾而被偏好或壓低。

**限制**：

- 前綴內部的順序偏差還在（DecisionRAG 裡的具體情況見〈Q4 位置編號是不是都當作接在 context 後面？〉）。
- 需要能自己控制位置編號和遮罩，也就是要有開源權重；API 模型做不到。
- 前綴很長時，attention 計算量隨長度平方成長，省下來的部分可能被抵消。

**相關做法**（一般知識）：推論框架的 prefix caching（如 vLLM）會在請求之間共用前綴計算，但不改位置編號；訓練時的 sequence packing 把多筆樣本串接起來並互相遮罩；speculative decoding 的 tree attention 讓多條候選路徑共用前綴。

### 樹狀導航的上限由節點描述決定

上層做決定時，審查員只看得到節點的短描述，看不到底下的內容。描述看不出某個分支有答案，那個分支就會被剪掉，而且救不回來。所以描述的品質直接決定整個系統的召回上限。論文在 Limitations 承認了這點，但沒有量化。

**沒有現成結構時怎麼建**（論文在 Wikipedia 上的做法，Appendix A.4、B.5）：

1. 每頁取「標題 + 第一句」，轉成向量（e5-base-v2）。
2. 用 k-means 分成 1,000 群。
3. 請 LLM（Qwen3-8B）讀每群的頁面標題，寫一句 30 字內的描述。
4. 描述必須點名比較不典型的成員。摘要天生會描述多數成員的主題，少數成員就從描述裡消失了，審查員也就不會為它們保留這一群。這個 prompt 設計沒有做消融驗證。

**有現成結構時**：章節標題、網址路徑、metadata 都可以當描述；樹不必處處一樣深，只在節點太大的地方多切一層。

**可以套用的地方**（推論）：任何「看描述選分支」的路由問題都適用，例如 agent 依工具描述選工具、依 skill 描述選 skill、多 agent 之間分派任務、RAPTOR 的摘要樹、PageIndex 的目錄導航。路由器再強，也受限於它看到的選項描述。

## 使用前要知道的限制

前面各節提到的限制集中在這裡，細節回到對應段落看：

- **「retriever-free」名不符實**：四個資料集的最佳成績都出自混入向量檢索候選的混合版，它需要事先建好的向量索引（〈補救剪錯的兩個後門〉）。
- **導航不一定有額外貢獻**：MD2D 和 MTRAG 上，導航和直接用 Jev 重排持平（〈提升來自導航，還是來自 Jev？〉）。
- **加速比不是公平比較**：硬體、平行度、模型大小都不同；大語料時成本反而比 GPT-5 重排高；Jev 1.13 只能透過 API 用（〈延遲與成本〉）。
- **MTRAG 標註有利益衝突**：部分正確答案由 GPT-5 補標，而 GPT-5 也是 baseline（〈讀表需要的最少知識〉）。
- **召回上限受節點描述限制**，論文沒有量化（〈樹狀導航的上限由節點描述決定〉）。
- **沒驗證或論文未交代的部分**：沒驗證的有候選在 context 內的順序偏差、$P(\text{yes})$ 絕對值能不能拿來對門檻；論文未交代的有 MTRAG 的 notepad 行為、決選題的實際問句（見〈Q1 每個判斷階段，模型的輸入和輸出到底長什麼樣？〉、〈Q2 同一個 context 放越多候選，判斷品質會變差嗎？〉、〈Q3 notepad 是直接放進段落層嗎？〉、〈Q4 位置編號是不是都當作接在 context 後面？〉）。

## 結論

- DecisionRAG 把檢索改成沿語料樹往下走：每一層把所有候選寫進同一個 context，由決策模型一次 forward pass 判斷哪些值得往下翻，最後出一題決選題排第一名；全程不生成 token，查詢時也不需要第一階段檢索器。
- 準確度遠勝 BM25 與「向量檢索 + 8B reranker」，和「向量檢索 + GPT-5 重排」大約打平；混合版在四個資料集上持平或小勝。
- 同一棵樹上把 GPT-5 的逐字生成換成決策模型的判斷，準確度相當，延遲快 34 到 145 倍。
- 兩個反直覺的結果：通用決策模型當重排器能勝過專門訓練的 8B reranker；沿樹導航勝在「排得準」，不是「找得全」。
- 最值得帶走的是兩個通用概念：多題共用一個 context 時，用「位置編號重疊 + 遮罩」消除題目順序偏差；樹狀導航的召回上限，由節點描述的品質決定。
