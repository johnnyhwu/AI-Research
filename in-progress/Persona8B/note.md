# MatrAIx 論文筆記：用大量虛擬使用者評估 AI 產品

Oct 28, 2026 · @YHHW

**論文：** *MatrAIx: Simulating the World with 8.3 Billion Persona Agents*（arXiv:2608.04205v1，2026 年 8 月 4 日）　https://arxiv.org/abs/2608.04205

## 三十秒版本

**一句話：** MatrAIx 是一套「讓大量虛擬使用者去試用產品、再統計結果」的測試系統；它把造人、操作、檢查三件事都做成可重跑的流程，但實驗顯示，結果主要取決於「用哪個模型來扮演」，而不是「扮演誰」。

- **造人（Persona 8B）：** 一個 persona（虛擬使用者）就是一份有 1,290 個欄位的檔案，每欄只能從固定選項裡選（例如年齡層、風險偏好）。合成的 persona 靠欄位之間的依賴關係逐欄抽出來，避免出現「20 歲、博士、退休」這種不可能的人；真人來源（維基百科傳記、商品評論、問卷）則轉成同樣格式，沒有證據的欄位留空（null）。公開版約 100 萬筆：真人來源 599,847、合成 400,000。
- **操作（Playground，論文的執行平台）：** 讓 persona 在四種環境裡使用產品：問卷、聊天機器人、網頁、App。每次試驗（trial）由「哪位 persona、做什麼任務、用什麼操作介面、哪個模型、哪顆隨機種子」五樣東西決定；試驗結束後，任務自帶的驗證器把留下的證據轉成有型別的結果。任務庫有 1,010 個規格，論文實際報告其中 8 個。
- **實驗發現：** 三個扮演的模型（GPT 5.5、Claude Opus 4.8、Claude Haiku 4.5）之間差很多：同一批 persona，在「糖果漲價後還買嗎」任務裡，猶豫的比例 GPT 98.3%、Opus 27.0%。說話風格類的設定大多能被執行（Opus 扮演，366/400 次 = 91.5%）；但年齡這類人口欄位的影響沒有被證明：GPT 與 Opus 自述的年齡層只跟隨機猜一樣，不同模型的答案在扣掉碰巧之後幾乎沒有一致（κ 中位數接近 0）。

## 1 問題與挑戰

真人測試太貴太慢，離線 benchmark 又看不到「不同的人用起來有何差異」，所以論文想用大量虛擬使用者補這個洞。

|  | 真人評估 | 離線 benchmark | 模擬使用者（本文） |
| --- | --- | --- | --- |
| 成本與速度 | 貴、慢（數週） | 便宜、快 | 便宜、快（數小時） |
| 看得到使用者差異 | 看得到 | 看不到，只量任務有沒有做對 | 想看到 |
| 可重跑 | 難 | 容易 | 容易（同一批人可重跑） |

論文的例子是寫程式的 agent：unit test 全過只代表功能正確，但新手想要解釋和小改動，專家想要簡短回覆和更大的自主權，同一個系統對兩種人的體驗可能完全不同，平均分數看不出來。

**一句話挑戰：** 要讓 LLM 扮演的「虛擬使用者」同時做到三件事：人群多樣又合理、能在不同產品裡真的操作，而且行為真的照設定走。換成最白話的講法：造出一群像樣的「人」，讓他們去用產品，還要證明他們演得像。三件事依序對應下面的「2a 怎麼造 persona」、「2b 怎麼跑模擬」和「3 實驗」。

## 2a 怎麼造 persona（回應挑戰 1）

一個 persona 就是一列 1,290 個選項：合成的靠欄位依賴逐欄抽出，真人來源轉成同一格式，沒有證據的格子留空。

### 2a-1 一筆 persona 長什麼樣

persona 是一份固定格式的表單：1,290 個欄位，每格只能從有限選項裡選（例如年齡層 18–24、25–34、35–44；英語程度從 Native 到 None）。合成的 persona 每格都填滿；真人來源的紀錄只填有證據的格子，其餘是 null，論文不補值。欄位分五大類：Background 238、Psychology 210、Capability 331、Behavior and Interaction 124、Lifestyle 387（原文 Table 1，Persona 8B schema overview）。

| 欄位（自編例子） | 合成紀錄 | 真人來源紀錄 |
| --- | --- | --- |
| age bracket | 25–34 | 35–44 |
| English proficiency | Native | Fluent (C1-C2) |
| risk tolerance | Risk-averse | null |
| Python | Advanced | Intermediate |
| time pressure | High | null |
| exercise frequency | Weekly | null |

兩種紀錄用的是同一份欄位清單，差別只在有沒有填滿。

### 2a-2 合成 persona：依賴圖逐欄抽樣

**為什麼不能各欄位獨立抽：** 只讓每個欄位的比例準確還不夠。各抽各的，可能抽出「20 歲、博士、退休」這種不可能的人（自編例子）。

**做法：** 每個欄位是圖上的一個節點。某個資料來源若直接報告了「A 欄位依 B 欄位拆開的分布」，就畫一條 B→A 的箭頭，表示 A 要等 B 抽好才抽。沒有父欄位的節點叫 root，直接用全人口比例抽；有父欄位的叫 child。抽的順序是先父後子（見【概念 1】）。整個 persona 的機率，是每一格「依父欄位」的機率連乘（論文 Eq. 3）：

```latex
p(x)=\prod_{i=1}^{d} p\left(x_i \mid x_{\mathrm{Pa}(i)}\right)
```

- x\_i：第 i 格的值，例如學歷。
- Pa(i)：第 i 格的父欄位集合；root 的集合是空的。
- 連乘符號：1,290 格的機率全部相乘。

自編數字：只看年齡與學歷兩格，p(age=25–34)=0.20，p(edu=Bachelor | age=25–34)=0.40，這兩格組合的機率是 0.20×0.40=0.08。學歷的機率會隨年齡改變，關聯就是這樣被保留的。實際不會列出所有組合，而是逐欄抽（見【概念 2】）。

**每一格怎麼抽：** 對這一格的每個候選值，依序做四步，最後按機率抽一個。

1. 先驗：不看任何父欄位時，全人口中取到這個值的比例。
2. 調整：父欄位改變機率。每個父欄位給一個比值（這個父欄位下的比例 ÷ 先驗），比值大於 1 表示更常見；多個父欄位的比值相乘，因為沒有任何來源提供「多個父欄位一起」的表。
3. 遮罩：只有 0 或 1。不可能的組合設為 0，直接排除。
4. 正規化：把分數加總成 1，變成機率。

調整與遮罩分開的用意：「很少見但可能」的人不會被誤殺，「不可能」的人才被真正排除。

**算例（論文 Table 6）：** 情境是語言＝英文、地區＝北美，要抽「英語程度」。Table 6 的說明寫明這些是示意用數字，不是實際部署的參數。

| 候選值 | 先驗 | 語言比值 | 地區比值 | 調整（兩者相乘） | 遮罩 | 分數（先驗×調整×遮罩） | 機率 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| None | 0.30 | 0.02÷0.30=0.067 | 0.10÷0.30=0.333 | 0.022 | 0 | 0.000 | 0.000 |
| Basic | 0.30 | 0.08÷0.30=0.267 | 0.20÷0.30=0.667 | 0.178 | 1 | 0.053 | 0.028 |
| Fluent | 0.25 | 0.30÷0.25=1.200 | 0.35÷0.25=1.400 | 1.680 | 1 | 0.420 | 0.224 |
| Native | 0.15 | 0.60÷0.15=4.000 | 0.35÷0.15=2.333 | 9.333 | 1 | 1.400 | 0.747 |
| 合計 | 1.00 |  |  |  |  | 1.873 | 1.000 |

以 Native 為例：先驗 0.15；語言說 Native 有 0.60，是平常的 4 倍，地區說 0.35，是平常的 2.333 倍，調整 = 4×2.333 = 9.333；分數 = 0.15×9.333×1 = 1.400；四個分數加總 1.873，所以機率 = 1.400÷1.873 ≈ 0.747。Native 從先驗的 15% 變成 74.7%。None 若沒有遮罩，分數約 0.0067，仍有約 0.35% 的機率被抽中（筆記自算），遮罩才讓它變成真正的 0。

### 2a-3 真人資料轉成同一格式

六個真人來源，依資料本身有多結構化，分四種轉法：已編碼的問卷答案查表（Stack Overflow 調查 113,120、GSS 63,532）；志願者自填（355）；編碼欄位查表加 LLM 讀自述（PRISM 1,487）；LLM 讀自由文字（Wikipedia 傳記 323,438、Amazon 評論 97,915）。合計 599,847，數字是公開 coreset 的筆數（原文 Table 2）。每一格都遵守同一條規則：沒有證據就留 null，並標明來源類型（直接證據、結構化主張、摘要推論、無依據）。對應關係見【概念 3】，LLM 抽取的信心值見【概念 4】。

## 2b 怎麼跑模擬（回應挑戰 2）

一次模擬（trial）由五樣設定組成，跑完留下證據包，再由任務自帶的驗證器轉成有型別的結果；四種環境只差互動方式與證據種類。

### 2b-1 一次 trial 由什麼組成

一次 trial 是「五樣設定」的組合：

- **persona：** 一筆 1,290 格的紀錄。
- **task（任務）：** 要做什麼、怎麼檢查。
- **agent（操作介面）：** 決定 persona 能看到什麼、能做什麼動作，例如對話介面或瀏覽器。
- **model（模型）：** 背後驅動它的 LLM，負責做決定。persona 紀錄配上模型才叫 persona agent。
- **seed（隨機種子）：** 讓抽樣與重跑可重現。

跑完留下 artifact bundle（證據包）：提交內容、軌跡、環境狀態。同一組設定對 N 位 persona 各跑一次叫 job；每個 trial 互不共用狀態，所以可以平行跑。五格可以各自獨立更換，只改一格、其他固定，就能做乾淨的對照。

&#91;embedded content: 一次 trial 的流程 · 五樣設定、三步輸出\]

上排五格是一次 trial 的設定，藍色小字是論文 5.3 節 meal-planning 任務的例子（persona 編號與 seed 是自編的）。往下是流程：執行、留下證據包、由驗證器轉成結果。

### 2b-2 四種環境

| 環境 | persona 做什麼 | 論文例子 | 留下的證據 |
| --- | --- | --- | --- |
| Survey 問卷 | 填問卷，做概念測試、價格敏感度 | 汽水漲 $2 還買嗎 | 結構化答案＋理由 |
| AI Chatbot 聊天機器人 | 跟被測的聊天機器人對話 | 機器人答錯又更正後，還會繼續聊嗎 | 完整對話、工具呼叫、目標是否解決 |
| Web 網頁 | 用瀏覽器自動化或 CUA 逛網站 | 不同預算的人找筆電 | 看過的頁面、動作、截圖、最終提交 |
| App 應用程式 | 用滑鼠、鍵盤或觸控操作原生 App | 找到並修改隱私設定 | 操作序列、最終 App 狀態、檔案或設定變更 |

CUA（Computer-Use Agent，電腦操作 agent）：看螢幕畫面、用滑鼠鍵盤操作電腦的 agent，用在 Web 與 App 環境。App 環境在 Docker 沙盒（隔離的容器環境）裡跑 Linux 桌面程式，macOS 與 iOS 則用遠端桌面或模擬器。四種環境共用同一套 trial 規格。

### 2b-3 一個任務怎麼寫

任務就是一份可重跑的實驗說明書，要寫四件事。右欄是論文 5.2 節的汽水漲價例子。

| 這一項 | 要寫什麼 | 汽水漲價例子 |
| --- | --- | --- |
| 測什麼 | 被評估的系統或產品 | 汽水的新價格 |
| 找誰測（cohort） | 要抽哪些 persona、抽多少、用什麼種子 | 不同收入、經濟動機的 persona |
| 情境與目標 | persona 看到什麼、要完成什麼 | 看到漲價，決定還買不買 |
| 證據 | 什麼回應或狀態算數、怎麼檢查 | 買或不買＋理由；檢查兩者都有 |

cohort 存的是「查詢條件加種子」，不是名單：同樣的條件加同樣的種子可以重抽出同一批人；換條件、保持產品與情境不變，就能比較不同族群。每次執行都記錄「想要的 cohort」與「實際跑出的 cohort」，失敗或缺漏的 trial 留在帳上，不事後補。

任務契約把三樣東西分開放，persona 只拿到其中一樣：

| 放在哪裡 | 放什麼 | 對應考試 |
| --- | --- | --- |
| persona 看到的指令 | 情境與目標（「汽水漲價了，你還買嗎？說明理由」） | 考卷上的題目 |
| 驗證器那邊 | 評分規則（「回答必須同時有購買意圖與理由」） | 老師手上的評分標準 |
| 產品那邊 | 產品帳密、怎麼連到被測產品 | 考場的鑰匙 |

論文只交代了「分開放」這個原則（5.2 節、Table 10）。為什麼這樣設計，論文未說明；推論：避免 persona 為了通過檢查而作答。

### 2b-5 驗證器：怎麼把證據變成有型別的結果

驗證器是任務自帶的檢查程式，原則是規則優先：

- 看得見的結果用程式規則檢查：輸出格式、必填題有沒有答、最終狀態、權限變更、副作用。
- 只有需要解讀的性質（清晰、同理、可信、persona 是否照設定）才交給 LLM 或人工評審，評審的結果會標明是評審給的，並保留它判斷時看的原文。
- 每一條結果是 typed finding（有型別的結構化結果）：名稱、型別（數字、類別、布林、文字）、值，以及指向支持它的證據。
- 報告先用不靠 LLM 的方式彙整（筆數、分布、排名），再選擇性加上 LLM 摘要；報告存任務版本、想要的與實際跑出的 cohort、模型與 agent 設定、驗證器版本，並連回每一筆 trial 的證據。

&#91;embedded content: 驗證器流程 · 規則優先、結果有型別\]

上半是單次 trial 的驗證：規則檢查先做，評審只在無法化成客觀條件時才出場，評審產生的結果會標明。中間是三條 typed finding，下半是彙整成報告。

任務產出、使用者行為、persona 是否照設定、執行失敗，這四類結果分開記，不混成一個分數；任務成功也不被當成「模擬像真人」的證據（5.2 節）。什麼情況算「無法化成客觀條件」而交給評審，論文未說明。

## 3 實驗

論文用 GPT 5.5、Claude Opus 4.8、Claude Haiku 4.5 三個模型扮演 persona，跑了八個任務共 18,189 次 trial。最重要的一個發現是：結果主要取決於「誰在扮演」。

### 實驗 A：換扮演者模型，結論會不會變

**這個實驗在問什麼：** 模擬結果的差異，主要來自「扮演誰」（persona 不同），還是「誰在扮演」（LLM 不同）？Candy Land（糖果漲價後還買嗎）這個任務同時回答了這兩邊。

先講分母與來源：每個模型各 1,000 位 persona（Table 13）。看的數字是「在新價格下猶豫的人占多少」。

&#91;embedded content: Candy Land：換模型與換 persona 子群的猶豫比例 · Table 12、附錄 F.6\]

**圖怎麼看：** 兩排用同一把 0 到 100% 的尺，看的都是「猶豫的人占比」。

- A 排：三個點散得很開，最高 98.3%（GPT）、最低 27.0%（Opus），差 71.3 個百分點（Table 12）。這排只改了一件事，就是換扮演者模型，persona 完全相同。
- B 排：每個模型內，把 persona 按經濟動機分四組，各組的猶豫比例擠在一小段裡。GPT 差 2.0 個百分點，Haiku 5.6 個百分點，Opus 至少 14.0 個百分點。校正後，經濟動機在三個模型下都不顯著（附錄 F.6）。各組人數論文沒列在文字裡。

**結論，三句話：**

1. 在這個任務裡，換模型造成的差異（71.3 個百分點）遠大於換 persona 子群造成的差異（最多十幾個百分點，而且統計上不顯著）。
2. 所以結果主要反映「誰在扮演」，不是「扮演誰」。
3. 這個實驗沒有真人資料對照，不能說哪個模型比較準，只能說模擬結果對模型很敏感。

## 4 整體評價

**一句話判決：** 基礎設施做得扎實，值得參考；但「用大量 persona 模擬市場」這個賣點，論文自己的實驗並沒有撐起來。

**判斷（推論）：** 較適合的用法是「找問題」：用多個模型、多種 persona 跑一遍，看哪些情境讓產品出現異常；不適合的用法是「估比例」：拿模擬出的百分比去推真實使用者。

## 5 值得帶走：Cohen's kappa

**一句話：** 原始一致率會騙人，因為答案偏向同一個選項時，隨便答也會大量撞答案；Cohen's kappa（κ）把這部分先扣掉，只看多出來的一致。

&#91;embedded content: κ 兩情況算例 · 100 位 persona，自編例子\]

**圖怎麼看：** 下面用 100 位 persona 算兩種情況（數字都是自編例子）。藍色格子是「兩個模型答案相同」的人數。兩張表的算法一樣：先算實際一致，再算「如果各自隨便答，會碰巧一致多少」，兩者相減，再除以「碰巧之外最多還能多一致多少」。

- 情況一：實際一致 82%，看起來很高。但兩個模型各自有 90% 的機率答「是」，光靠碰巧就會一致 82%，所以 κ = 0，沒有任何額外的一致。
- 情況二：實際一致 90%，碰巧只會一致 50%，多出來的一致很多，κ = 0.80。

**公式：**

```latex
\kappa=\frac{p_o-p_e}{1-p_e}
```

- p\_o：實際一致的比例，也就是兩個模型給出相同答案的 persona 占多少。
- p\_e：如果兩個模型各自按自己的答案頻率獨立作答，預期會一致的比例。
- κ = 1 表示完全一致，κ = 0 表示不比碰巧好，κ 小於 0 表示比碰巧還不一致。

**使用提醒：** κ 只量一致、不量對錯，兩個模型都答錯也可以 κ 很高。一致率高但 κ 很低，通常代表答案太集中在單一選項，不代表兩邊有分歧。

**在這篇論文裡的用法：** 論文把 κ 用在「模型對模型」：同一批 persona 交給三個模型各演一次，比較 88 個欄位上兩兩的答案是否一致，三組配對的 κ 中位數是 0.000、0.000、+0.001（Table 15）。意思是扣掉碰巧之後，不同模型對同一批 persona 幾乎沒有共同的走向。這可能是兩個模型都沒怎麼用 persona，也可能是各自用法不同；論文未說明是哪一種（推論）。論文也未說明 κ 沒有定義的欄位（兩邊都只給同一個答案）怎麼處理。

### 【概念 1】root 與 child 怎麼決定，欄位依賴只有一層嗎

**一句話：** root 與 child 不是事先指定的，由「手上有沒有『依 B 拆開的 A』的統計表」決定；依賴可以有很多層。

論文的規則是：只有資料來源直接提供「A 欄位依 B 欄位拆開的統計表」時，才畫一條 B→A 的箭頭。以下三個統計表是自編例子：

&#91;embedded content: DAG 示意 · 簡化版，實際可多層\]

灰色是 root，藍色是依父欄位抽的 child；這是簡化的示意圖，不是論文的完整依賴圖。

| 手上有的統計表（自編例子） | 意思 | 結果 |
| --- | --- | --- |
| 各年齡層各占多少 | 年齡不用看別的欄位就能抽 | age 沒有父欄位，是 root |
| 每個年齡層的學歷分布 | 學歷要先知道年齡才抽得準 | age → education，education 是 child |
| 每種「語言＋地區」組合的英語程度分布 | 英語程度要先知道語言和地區 | language、region → English proficiency |

**不只一層：** 一個欄位的父欄位自己也可以有父欄位，抽樣只要求「父欄位先抽」，所以 A→B→C 沒有問題：B 依 A 抽，C 再依 B 抽。三層鏈的機率是 p(a)×p(b|a)×p(c|b)；自編數字：0.20×0.40×0.50=0.04。

**畫邊有三道把關：** 來源審查（有直接報告條件分布才加邊）、確認父欄位對子欄位的值域是真有意義而不只是統計相關、LLM 輔助補漏後由人逐條接受或拒絕（附錄 C.1）。

**標註：**

- root 是「沒有邊的結果」，是推論；論文只說 root 用 categorical prior（類別式的全人口比例）。
- 邊的方向怎麼定，論文未說明；推論：跟著來源表格的拆分方向。
- 最深有幾層，論文文字未說明；完整依賴圖在附錄 C.1 的 Figure 5。
- 另有 18 個隱藏的 root（如 latent\_financial\_security），設計上就是 root，用來協調一整族欄位，不會輸出到 persona 裡（附錄 C.1）。

### 【概念 2】實際怎麼抽樣，為什麼不用列出所有組合

**一句話：** 逐欄走一遍：每一格只依父欄位已經抽到的值，得到自己那一格的小分布，再抽一個值；完整的聯合機率不用算，也不用存。

**為什麼不能列出所有組合：** 組合總數是各欄位選項數相乘。1,290 個欄位即使每欄只有 2 個選項，也有 2 的 1,290 次方種組合，列不完。

**做法：** 論文稱為 forward sampling（按順序逐欄抽，論文 Eq. 5）。每個 persona 只需要 1,290 次小抽樣，每次只面對一欄的幾個選項。重複 N 次就得到 N 個 persona（Eq. 8）；種子固定即可重現，並分成多個 shard 平行生成（附錄 C.1）。

**數字例子（走過三格）：** 第一、二格的數字是自編例子，第三格是論文 Table 6 的結果。第二格的分布會隨第一格抽到的年齡改變，這就是關聯被保留的地方。

### 【概念 4】regex 的信心值從哪來，合併階段怎麼用信心值

**一句話：** regex 的信心 0.7 是設計者固定給的常數，不是算出來的機率；合併階段怎麼用信心值，論文沒有說清楚。

用 LLM 抽取自由文字時，有兩路並行：regex（規則比對）找原文裡直接出現的選項字樣，LLM 評審只看檢索到的相關欄位與固定選項，可以棄權。每一格紀錄都附一個信心欄位，但它只是標記可靠度的分數，不是經過校準的機率。三種來源的信心值刻度不同，不能直接比較：

| 來源 | 信心值 | 怎麼來 |
| --- | --- | --- |
| 原始精確答案（查表與志願者自填） | 1.0 | 受訪者自己答的，覆蓋任何推論 |
| regex 字面比對 | 0.7 | 設計者固定給的常數；0.7 怎麼定，論文未說明 |
| LLM 判斷 | 模型自己給的 | 是模型自述還是 logprob 算的，論文未說明 |

**合併階段（附錄 D.1、D.4）：** 兩邊結果按欄位對齊、分開留存、不一致的保留下來供稽核。最後選誰、信心值有沒有參與選擇，論文未說明。我讀到的 D.1 該句在換頁處中斷，可對照原文確認。

**推論：** 在我讀到的全文裡，信心值被存起來，但找不到任何地方用它來過濾或加權。可信度主要由來源類型（直接證據、結構化主張、摘要推論、無依據）和「證據是否出自原文」決定。

### 【概念 5】風格設定被遵守，年齡自述卻只是隨機：為什麼看起來矛盾

**一句話：** 兩個結果測的是不同東西：說話風格大多被執行，但年齡這類人口欄位在這份證據下沒有被證明被用上。

|  | B 受控行為遵守 | C1 年齡自述 |
| --- | --- | --- |
| 測什麼 | 說話風格（表情符號、囉嗦、禮貌…） | 人口欄位（年齡層） |
| 怎麼判 | LLM 評審讀軌跡，二選一 | 自述年齡層是否等於設定，六選一精確比對 |
| 隨機基準 | 約 50%（筆記推算，論文沒報基準） | 16.7% |
| 結果 | Opus 91.5%、GPT-5.6-sol 79.2%（Haiku 沒測） | GPT 5.5 16.3%、Opus 16.9%、Haiku 100% |

B 的 50% 基準是推算：模型若完全忽略 persona，正向與反向兩組會輸出同一種風格，剛好一組成功、一組失敗，整體約 50%。C1 是哪個任務，論文文字沒標；推論是有六個年齡組的 Annual checkup。

**兩者為什麼並存：** 論文未說明。推論有兩個：年齡這一格可能沒有被當成要演出的內容（論文只說 persona 會被轉成給模型的指令，沒說每一格都轉，附錄 E.3）；或自述題的問法讓模型以「自己」作答。

**合起來怎麼讀（推論）：** 實驗 A（persona 子群差異小且不顯著）、C1、C2 都指向人口欄位的影響很弱；只有 B 偏樂觀，而且它測的是最容易被執行的風格。所以「persona 被遵守」較準確的說法是：風格類被遵守，人口類在這份證據下沒有被證明。
