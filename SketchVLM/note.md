# Chapter 1: 論文核心背景與待解決挑戰

在本章中，我們探討為什麼在多模態大模型（VLM）飛速發展的今天，**SketchVLM** 這種標註框架的出現是必然的。核心矛盾在於：模型越來越聰明，但人類與模型的「溝通透明度」卻沒有跟上。

## 1.1 VLM 在視覺推理中的侷限 (The Verification Gap)

雖然現有的頂級模型（如 GPT-4o 或 Gemini 系列）能產生流暢的文字，但在處理「視覺推理」任務時存在嚴重的黑盒效應。

*   **文字回應的空洞性**：當使用者詢問複雜的空間問題（例如：汽車維修、物理路徑）時，文字往往難以精確對應到像素位置。
*   **視覺幻覺 (Hallucination)**：模型可能文字答對了，但其實它是「猜」對的，或者是看錯了位置卻給出對的答案。使用者無從驗證模型的思考路徑。

| 特性 | 傳統 VLM 回應 | SketchVLM 回應 |
| :--- | :--- | :--- |
| **輸出形式** | 單純文字塊 (Block of text) | 文字 + 向量標註圖層 (SVG Overlay) |
| **可驗證性** | 低（需讀完文字後自己對照圖片） | 極高（一眼看出模型在指哪裡） |
| **推理展示** | 隱藏在神經網路內部 | 視覺化展示推理軌跡 (Visual CoT) |

## 1.3 SketchVLM 的核心解決方案 (Value Proposition)

針對上述問題，SketchVLM 提出了一個優雅的框架，其核心邏輯可以簡化為以下流程：

### 🔄 技術邏輯流程圖
`輸入影像` + `網格輔助` $\rightarrow$ `VLM 產出 XML 繪圖代碼` $\rightarrow$ `數學演算法平滑化` $\rightarrow$ `SVG 向量層疊加`

### 核心價值三大支柱：
1.  **非破壞性標註 (Non-destructive)**：
    *   透過 **SVG (Scalable Vector Graphics)** 技術，在圖片上蓋上一層「透明投影片」。這保證了原始數據的完整性，使用者可以隨時編輯或移除標註。
2.  **訓練豁免 (Training-free)**：
    *   這是一個 **模型無關 (Model-agnostic)** 的框架。它不需要重新訓練模型，只需透過精妙的 `System Prompt` 就能讓現有的強大 VLM 變身為畫家。
3.  **視覺思維鏈 (Visual Chain-of-Thought)**：
    *   將模型的「思考過程」直接畫出來。這不僅僅是為了好看，更是為了讓標註能與模型的文字答案達成 **高度一致 (Faithful)**。

# Chapter 2: 空間感知的基礎：視覺提示與網格系統

為了讓 VLM 能夠在影像上「指哪畫哪」，SketchVLM 並非依賴模型的直覺，而是為模型提供了一個明確的**外部參考系**。這就是本章的核心技術：**座標網格 (Coordinate Grid)**。

## 2.1 座標網格的工程實作 (The Grid Engineering)

在討論中我們特別關注網格是否會破壞圖片，答案是：**不會**。

*   **技術手段：畫布擴展 (Canvas Extension)**：
    *   系統並不是直接在原始影像的像素上畫線，而是使用影像處理工具（如 Pillow）在影像的**左側 (Y軸)** 與 **下方 (X軸)** 拼接（Padding）出額外的白色邊框。
    *   **優點**：原始影像像素保持 100% 完整，避免了「內部網格」可能遮擋物體特徵或干擾模型辨識的問題。
*   **視覺化標示**：
    *   在擴展出的邊框上，標註刻度線與對應的數字（例如 0, 100, 200...）。
    *   座標系統與影像解析度自適應對齊（例如：1000x1000 的解析度對應 0-1000 的刻度）。

### 🖼️ 視覺化舉例：網格拼接流程
`[原始影像 (500x500)]`  
$\downarrow$ (拼接左邊框與底邊框)  
`[左刻度(Y)] + [原始影像] `  
`          + [底刻度(X)]`

# Chapter 3: 定義繪圖語法 —— 系統提示詞與結構化輸出

如果說座標網格是給了 AI 一把尺，那麼**繪圖語法協定**就是教 AI 如何撰寫「繪圖說明書」。SketchVLM 不要求模型輸出像素，而是要求它輸出結構化的 XML 代碼。

## 3.1 溝通協定：為何選擇 XML 格式？

作者在系統設計中捨棄了 JSON，轉而使用 **XML-style 標籤**。這是因為語言模型對於「成對標籤」的生成具有極強的穩定性，且方便後端正則表達式（Regex）精準抓取。

*   **標籤結構**：每一筆劃被包裹在 `<sN>...</sN>` 中（$N$ 為序號）。
*   **座標語法**：採用 `xAyB` 拼接格式（例如 `x500y100`）。
    *   **技術細節**：將 $x$ 與 $y$ 連結成單一 Token，能有效減少模型在輸出座標對時可能產生的配對偏移錯誤。

## 3.2 繪圖原語 (Drawing Primitives) 與指令細節

模型被教導使用一組預定義的幾何動作來描述視覺思考。

### 🛠️ SketchVLM 繪圖原語一覽表
| 形狀類型 | 標籤要求 | 技術關鍵與「小撇步」 |
| :--- | :--- | :--- |
| **自由繪圖 (Freehand)** | `<points>` 列表 | 用於複雜路徑。需提供連續座標以描述軌跡。 |
| **直線 (Straight Line)** | 僅需起點與終點 | 結構簡單，適用於指向或簡單劃線。 |
| **矩形 (Box/Rectangle)** | 順序提供四個角點 | **銳角處理**：在轉角處連續輸出兩次座標（例如 `...xAyB, xAyB...`），強制後端演算法不在此處進行平滑化。 |
| **箭頭 (Arrow)** | 拆解為「箭身」與「箭頭」 | 確保導向性明確。 |
| **文字標註 (Labeling)** | `<text>` + 錨點座標 | 文字大小與顏色由模型根據背景對比度主動選擇。 |

## 3.3 核心參數：`<t_values>` 的設計與作用

這是在討論中我們深入探究的部分。模型不僅要給出「點」，還要給出「節奏」。

*   **定義**：$t$ 是從 `0.0` 到 `1.0` 的數值，代表一筆劃的百分比進度。
*   **用途**：
    *   告知後端渲染引擎，點與點之間的「先後順序」與「相對距離」。
    *   它是實現**第四章：貝茲曲線平滑化**不可或缺的輸入參數。沒有 $t$，演算法就無法計算出平滑的曲線切線方向。

# Chapter 4: 幾何生成的靈魂 —— 三次貝茲曲線與最小平方法

VLM 本質上不具備精確的繪圖能力，它輸出的座標往往是離散且略微抖動的。本章介紹 SketchVLM 如何透過經典的數學演算法，將這些「不完美的點」轉化為「優美的向量軌跡」。

## 4.1 三次貝茲曲線 (Cubic Bézier Curves)：磁鐵與拔河的藝術

貝茲曲線的強大在於：它不需要定義線條上的每一個點，只需要定義 **4 個控制點** 就能描述一條極其平滑的曲線。

### 數學核心：四點結構
*   **端點 ($P_0, P_3$)**：線條的起點與終點，線條必須穿過這兩點。
*   **控制點 ($P_1, P_2$)**：**「磁鐵點」**。它們不在線條上，但會像磁鐵一樣把線條拉向自己。
    *   $P_1$ 決定線條離開起點時的切線方向。
    *   $P_2$ 決定線條進入終點時的切線方向。
*   **參數 $t$**：從 $0$ 到 $1$ 的流逝。當 $t=0.5$ 時，數學公式會精算出畫筆在該時間點應處的座標。

### 📊 繪圖技術對比表
| 特性 | 直線連接 (Polyline) | 三次貝茲曲線 (Bézier) |
| :--- | :--- | :--- |
| **數據需求** | 需要大量密集座標點 | 僅需少數關鍵點（通常 4 個） |
| **視覺效果** | 生硬、有鋸齒感、像機器人 | 平滑、流線感、像人類手繪 |
| **VLM 負擔** | 高（需輸出極多座標，容易出錯） | 低（僅需描述大致趨勢） |

## 4.2 橋樑演算法：最小平方法 (Least Squares Fitting)

這是我們討論中最核心的疑難雜症：**模型給的是「路徑點」，但數學要的是「控制點（磁鐵）」，該怎麼轉化？**

### 為什麼需要最小平方法？
VLM 的直覺是：「球會經過 A, B, C 這幾個位置」。但 A, B, C 是在軌跡上的點。最小平方法的作用就是擔任 **「翻譯官」**：
1.  **收集輸入**：接收 VLM 給出的離散座標點 $\{(x_j, y_j)\}$ 與時間參數 $\{t_j\}$。
2.  **定義誤差**：假設一條貝茲曲線，計算這條曲線到 VLM 給出的點之間的「距離平方和」。
3.  **尋找最優解**：透過微積分運算，反向推導出 **$P_1$ 與 $P_2$（控制點）** 的座標，使得這條曲線能「最不委屈地」穿過或貼近所有 VLM 給出的點。

### 🔄 擬合流程圖
`VLM 輸出 5 個抖動的路徑點` $\rightarrow$ `最小平方法運算` $\rightarrow$ `計算出 2 個最佳磁鐵位置 (P1, P2)` $\rightarrow$ `生成平滑 SVG 曲線`

---

## 4.3 實例分析：物理軌跡與字母繪製

*   **物理掉落軌跡 (Ball Drop)**：
    *   模型只需輸出球在彈跳過程中的三個關鍵點，最小平方法就能補完拋物線的弧度，使其看起來符合物理規律。
*   **曲線形狀 (如字母 C 或蘋果)**：
    *   模型只需給出起點、終點和彎曲處的一個點，系統就能自動生成完美的圓弧。

*   **解決「VLM 數學不好」的問題**：

# Chapter 5: 標註的可視化工程與多輪互動流

在本章中，我們關注標註如何保持清晰（不被背景吃掉），以及 SketchVLM 如何透過多輪對話將「靜態標註」轉化為「動態教學」。

## 5.1 標註的可視化工程：自適應樣式 (Adaptive Styling)

為了確保標註在任何背景影像下都清晰可見，SketchVLM 採用了「大腦決策」與「渲染保護」雙重機制。

### 🎨 自適應設計策略表
| 屬性 | 實現方式 | 技術細節 |
| :--- | :--- | :--- |
| **顏色自適應** | 模型主動決策 | VLM 分析影像背景色彩後，於 XML 中指定具高對比度的 Hex 色碼（如 `color="#ff0066"`）。 |
| **大小自適應** | 動態比例調整 | 根據物體在影像中所佔的像素比例，調整文字標籤 (`fontSize`) 與線條粗細。 |
| **可讀性保護** | 渲染端文字描邊 | 在 SVG 渲染時，自動為文字加上對比色的外框（Halo Effect），確保標註不因背景複雜而模糊。 |

## 5.2 單輪與多輪生成流 (Single-turn vs. Multi-turn)

這是我們討論中關於「教學邏輯」的核心。SketchVLM 支援兩種截然不同的互動模式。

### 🔄 模式對比與選擇
| 特性 | 單輪模式 (Single-turn) | 多輪模式 (Multi-turn) |
| :--- | :--- | :--- |
| **行為模式** | 一次給出所有標註與答案 | 畫一筆、說一句、等回饋 |
| **適用場景** | 快速診斷、物理路徑預測 | 軟體操作教學、複雜維修指南 |
| **系統壓力** | 低（單次 API 調用） | 高（需多次上傳與處理影像） |
| **準確度** | 優秀（模型能預先規劃） | 穩定（透過逐步校正減少誤差） |

### 🛠️ 多輪模式的「反饋閉環」流程
1. `User 問問題` $\rightarrow$ 2. `VLM 生成第一筆標註 <s1>` $\rightarrow$ 3. `系統渲染標註至原圖` $\rightarrow$ 4. **`已標註圖 + XML 紀錄 餵回模型`** $\rightarrow$ 5. `VLM 生成下一筆 <s2>`。

## 5.3 多輪實作關鍵：文字歷史的重要性

在討論中我們提到，為什麼模型在多輪對話中需要看「以前的座標」？

*   **視覺資訊的侷限性**：單看「畫好的圖」，模型難以精確辨識線條末端的像素座標，導致下一筆畫無法完美銜接。
*   **消融實驗結論 (Appendix D.10)**：必須提供 **「渲染後的影像」+「XML 標註歷史紀錄」**。文字紀錄提供了精確的「數字記憶」，影像提供了「空間感」，兩者結合才能實現連貫的引導。

## 6.1 七大基準測試任務 (The 7 Benchmarks)

論文在 **Section 4.1 (Page 6)** 與 **Appendix B (Page 27)** 詳細定義了測試場景：

3.  **畫出形狀 (Drawing Shapes)**：在物體周圍畫出矩形或橢圓。
4.  **零件標註 (Part Labeling)**：對物體細部進行命名與定位。
5.  **迷宮導航 (Maze Navigation)**：測試路徑規劃與障礙物避障。
6.  **物理直覺 (VPCT - Video Physics)**：預測球落入哪個容器。
7.  **進階物理 (Ball Drop)**：模擬複雜的掉落與彈跳軌跡。
